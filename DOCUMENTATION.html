The qa plugin turns plain-language feature descriptions into a deterministic Playwright end-to-end suite. An AI authors the tests; plain Playwright replays them nightly at near-zero cost; the AI is called back only when something breaks.

The core idea

Run the LLM only where it's irreplaceable

The expensive part of an AI-driven test is running the LLM. So the toolkit spends LLM tokens in exactly two places — authoring a spec (once) and triaging a failure (only when red) — and nowhere else. The nightly regression run is plain npx playwright test: deterministic, no agent in the loop, ~$0 LLM cost.

That yields one hard rule the whole design enforces: never run an LLM on a green build. The healer is invoked only on a failing test.

This "AI authors + deterministic replay" pattern isn't unique here — Meta (TestGen-LLM), Microsoft (Playwright Agents), Airbnb, Stripe and Uber all converged on it independently.

What it's for — and what it isn't

In scope

End-to-end / integration tests that drive a real browser against a staging / QA deployment of a web app.

Out of scope
  • Unit / component / contract tests → Vitest / Pact
  • Performance / load → k6 / Locust
  • Security DAST → ZAP / Burp
  • Native mobile → Playwright can't drive iOS/Android

Architecture

A marketplace, a plugin, and a "brain vs body" split

The repo is a private Claude Code marketplace hosting one plugin, qa. A plugin can only ship Claude configuration (agents, skills) — the brain. It can't install a project's runtime files, so those — the body — are stamped into each project by /qa:init.

The brain — shipped by the plugin

Live; auto-updates on plugin upgrade.

  • agents/ — 6 subagents
  • skills/ — 27 SKILL.md: the 21 /qa:* commands + 6 capability helpers
  • reference/DESIGN.md — the rationale
The body — stamped by /qa:init

Per-project, one-time. Fixes reach existing projects via /qa:init --resync.

  • package.json, playwright.config.ts, tsconfig.json
  • CLAUDE.md — the per-project policy / source-of-truth
  • .claude/settings.json — writable-path + deny rules
  • .mcp.json + .mcp.explore.json — two-config MCP
  • scripts/, fixtures/, .env.example
Why it matters: upgrading the plugin refreshes the brain instantly, but a fix to a template file only reaches new projects. /qa:doctor detects substrate drift; /qa:init --resync repairs it (backing each changed file up to .qa-bak, never touching your .env or CLAUDE.md). No subagent can spawn another — handoffs route back through the orchestrator via STOP-and-return messages or artifacts/.healer-needs-* sentinels.

Reference · 6 subagents

The brain

Each agent has a narrow role, a fixed tool set, and a strict writable-path boundary. None can spawn another. No agent pins a model — the tiers below are the operator-set guidance.

exploration

Explorer

Builds the context layer — captures domain vocabulary, never selectors. Verifies the hot tier; walks one area at a time.

writes → specs/_context/

ideation

Ideator

Rotates the SFDIPOT lenses → a candidate-case checklist. The human is the gate. Writes no tests.

writes → specs/ (.cases.md)

planner

Planner

Owns the assertion contract. Turns a story/bug into one spec + YAML oracle. Never writes .spec.ts.

writes → specs/

generator

Generator

Compiles spec → deterministic .spec.ts, verifies green, authors metamorphic twins, and fault-injects each must_fail_when to prove the oracle really fires.

writes → tests/ · page-objects/ · fixtures/ · bugs/

reviewer

Reviewer

Read-only PR gate. Blocks green-but-empty / -wrong tests. The only enforcement of the assertion contract — no hooks ship, so it is pinned to a high-capability model.

writes → nothing

healer

Healer

Invoked on failure only. Classifies into one of 10 buckets; patches selectors/waits or files a bug. Never touches assertions.

writes → tests/ · page-objects/ · bugs/ · heal-log

The reviewer's checks — the load-bearing gate

Any Fail blocks the PR; Warn is surfaced, not blocking.

CheckLevelCatches
1 · failable expectFaila test with no expect() that can fail
2 · step→assertion coverageFailsteps performed but nothing asserted (green-but-empty)
2b · must_fail_when reified/waivedFaila declared invariant that isn't an oracle key or explicit waiver
2c · oracle discriminating-powerWarna valid but non-discriminating key (text_visible where intent needs count_equals)
2d · oracle value fidelityFailright key, wrong value (green-but-wrong)
2e · equality-invariant precondition scopeWarnan equality oracle with no declared invariant_holds_when domain (green-but-over-broad)
3 · no unlinked fixme/skip/failFaila parked test with no bugs/ link
4 · closed oracle vocabularyFailan off-vocab key or wrong argument shape
5 · no waitForTimeout / networkidleFailbanned waits, in tests and page objects
6 · metamorphic twins exist + agreeFailnew spec with no twins, or a twin that disagrees (a fully-skipped twin run — no BASE_URL — is reported SKIPPED, never a vacuous PASS)
7 · context freshnessWarna stale or draft/REVIEW-banner context file
8 · site validityFaila site: not declared in sites[]
9 · locator policyFailXPath/CSS or chained .locator('css')
10 · factory enforcementFailan entity with a factory not using the factory: form
11 · hygieneFail.only(), hardcoded creds, inline base URLs, missing tag
12 · POM abstraction sanityWarnover- or under-abstraction of page objects
13 · parallel-safetyFaila state-mutating spec without worker isolation / serial mode; also the cross-feature case — one spec mutates a shared seed entity (deactivates/deletes a seeded user) another spec depends on as a fixture/owner (per-feature-green, combined-run-red)
14 · approved-case traceabilityWarnan approved .cases.md case with no scenario and no waiver (green-but-incomplete)
15 · healed-locator driftWarna heal that broadened a locator (.first()/getByText downgrade) — diff-aware; with no git baseline, falls back to a stale-testid full-scan (a spec/_context getByTestId('X') whose X no POM/test uses)

The healer's 10 buckets

Patch it (selectors / waits only):

broken-locator missing-wait

Hand off via a sentinel / escalate:

changed-text stale-context auth-stale data-drift contract-change

File a bug / leave red:

env-infra expected-failure product-bug

The anti-drift rule, verbatim:

"Never change the assertion contract — only selectors / waits."

Key concept · the oracle

The closed vocabulary — 16 keys, no free-form assertions

Every assertion must use one of exactly 16 keys. "Should look right" is unfalsifiable; a fixed set forces every assertion to mean something a reviewer can mechanically check. An agent cannot invent a new key — the reviewer's Check 4 fails an off-vocab one.

01
text_visible
"<string>"
02
url_matches
"<regex-or-literal>"
03
count_equals
{ locator, n }
04
value_between
{ locator, range:[min,max] }
05
error_shown
"<string>" (exact)
06
no_order_created
<bool>
07
attribute_equals
{ locator, attr, value }
08
element_state
{ locator, state }
09
network_response_status
{ url, status }
10
response_body_contains
{ url, text }
11
download_received
{ filename?, min_bytes? }
12
clipboard_contains
"<string>"
13
storage_state
{ cookies?, localStorage? }
14
upload_accepted
{ selector_role, name }
15
dialog_dismissed
{ type, accept? }
16
a11y_violations_below
{ max_critical, max_serious }
Deliberate gap: there is no relational / exact-equality key (value_equals). A key the reviewer couldn't structurally validate would weaken the closed-vocab guarantee. The set is mirrored across the planner, generator, reviewer, doctor and coverage — adding a key means editing every enumerating mirror in one commit.

Key concept · why tests can't fake green

The oracle defenses

The most dangerous failure isn't a flaky test — it's a test that stays green while no longer testing what it claims. LLM-authored tests are especially prone to it. Every defense answers that one problem:

Closed vocabulary

Assertions can't be free-form prose — only the 16 keys.

Step → assertion coverage

Every step must carry a real, failable expect(). The cheapest fake is to perform steps and assert nothing.

Assert intent, not behavior

The oracle encodes what correct means, not what the app does today — so today's bug isn't baked in as tomorrow's expected result. This is why assertions are sacred and owned by the planner.

must_fail_when + negative control

The generator fault-injects each declared invariant to prove the oracle actually goes red. A blind oracle blocks.

Metamorphic twins

A check needing no ground-truth: does an invariant-preserving transform keep the output equal? (Reorder a cart → total unchanged.)

The reviewer, by discipline

There are no PreToolUse hooks — no real-time guard. The reviewer at PR time is the backstop, precisely because nothing else enforces the contract.

Three-tier context

Selectors drift faster than any doc — so context is split by volatility, not stuffed in one file.

HotDurable facts (sites, auth, env). Always loaded, human-owned.
AreaPer-area vocabulary + routes. Dated, volatility-tiered.
ColdSelectors — pulled live at generate time, never cached.

CLI vs MCP

@playwright/cli is the default transport; Playwright MCP (bundled with Playwright 1.62+ via npx playwright mcp; the standalone @playwright/mcp package is legacy) is reached for only in exploration / interactive healing.

  • CLI wins on predictability & hygiene — ~68 vs ~3,600+ tokens of tool schema, no memory-leak.
  • MCP wins on wall-clock and, with caching, $/test. "CLI always wins" is false.
  • Implemented as a two-config pattern: default .mcp.json is empty, so plain runs pay no MCP cost.

Safety & quickstart

Rails, then the five commands to a first test

Safety rails

  • Never point BASE_URL_* at prod. Two guards: an advisory shell guard on every run, and an enforced globalSetup that throws before any browser opens. Both fail closed on the shipped CHANGEME placeholder.
  • Writable-path separation — writes only under tests/ specs/ page-objects/ …; config files are deny-listed (which is why fixes need --resync, not an in-place patch).
  • Credentials via env only — agents can't write .env; passwords are always password_env, never logged.
  • /qa:batch-fix proposes one pattern and waits for confirmation (high blast radius). The reviewer fails closed on inconclusive runs.

Honest limits

What it deliberately does not claim

These concessions are intentional. They're the most valuable part of the design doc — kept here so the tool never sounds more complete than it is.

A green a11y gate ≠ accessible

Automated scanning catches ~30–40% of WCAG issues, and AI "fixes" often satisfy the scanner while worsening the screen-reader experience. A human must review a11y fixes.

No mutation gate for .spec.ts

Mutation testing covers pure-TS units only. For browser tests, must_fail_when + negative control is the substitute — and only for declared invariants.

Visual regression needs a specialist

Self-hosted screenshot diffs catch gross breakage; the perceptual / cross-browser long tail needs visual-AI (Applitools / Chromatic / Percy).

A wrong spec is un-automatable

Every defense guards drift inside a correct spec. If the human encodes the wrong business rule, no oracle fixes it — which is why the human approval gate on ideation is non-negotiable.
