A Claude Code plugin (`qa/`) for AI-authored, Playwright-replayed E2E testing.
Thesis: AI authors specs + tests, Playwright replays nightly at ~$0 LLM cost, AI triages
only on failure. Claimed moat = the **oracle-defense layer** (closed 16-key assertion
vocabulary, metamorphic twins, fault injection, blocking reviewer) that Microsoft's official
Playwright Agents deliberately do not provide.

Layout: **7 agents** (6 until session 7's generator→compiler+verifier split), 23 skills (19 user-facing + 4 capability helpers), `templates/` runtime
substrate stamped by `/qa:init`, `reference/` docs, `bin/qa-scaffold`.

## 4b. Prod-guard parity — findings (session 4, 2026-09-06)

**Headline: the two layers agree. The safety rail is sound.** This was the one unexamined
thing flagged as "divergence = real hole"; it was tested, not eyeballed, and no hole was found.

**Method.** Differential harness, not reading. The real `PROD_RE`, `PLACEHOLDER_VALUE_RE`,
`PLACEHOLDER_HOST_RE` and `hostOf()` were extracted from `prod-guard.ts` **by line number**
(so the shipped source is under test, not a retype); `prod-guard.sh` was executed for real under
`env -i` with a controlled environment. 35 URL-shape cases + 20 env-shape cases = **55 cases,
54 identical verdicts.** Corpus covered: prod/production/prod1/prod01, the `product`/
`reproduction`/`prodapi` near-misses, `admin-prod`, all scheme forms (`https://`, uppercase,
no-slash `https:`, protocol-relative, bare host, `host:port`), greedy-userinfo
(`user:p@ss@prod…`), CHANGEME/`<>`/RFC-2606 placeholders and their near-misses
(`myexample.com`, `example.co.uk`, `acme.example.company.com`), IPv6, every `QA_ALLOW_PROD`
value, secondary-var screening, and the unscreened-var boundary.

**1. One divergence — diagnostic only, no safety impact.** `BASE_URL_APP` set-but-EMPTY with a
prod `BASE_URL`: **both REFUSE** (exit 1 / throw), but `.sh` reports *both* reasons (empty
primary AND the prod secondary) while `.ts` throws on the empty primary and never reaches the
loop. Different message, same fail-closed verdict. Not worth "fixing".

**2. `.env` precedence differs between the layers — but is NOT exploitable.** `.sh` does
`set -a; . .env` (**`.env` wins** over an already-exported shell var); `.ts` uses
`dotenv.config()` (**shell env wins**, dotenv does not override by default) — verified
empirically both ways. This looked like a hole and is not, because **each guard matches its own
consumer**: the CLI-driving paths use the identical `set -a; . "${CLAUDE_PROJECT_DIR:-.}/.env"`
idiom as `.sh` (`explore/SKILL.md:25`, `intake/SKILL.md:76`, `exploration.md:47`), and
`playwright.config.ts:15` uses the same bare `dotenv.config({quiet:true})` as `.ts`. So each
layer screens exactly the value its own consumer will use. Worth documenting, since both files
claim to "mirror exactly" and neither mentions this.

**3. 🔴 The real gap: lockstep is only 1/4 ENFORCED.** `doctor` Check 8 pins the prod-marker
regex literal in **both** files (`[0-9]*` / `\d*`) — good. But the files demand three MORE
lockstep pairs in their own comments, and **nothing checks any of them**:
   - the screened var-name set (`BASE_URL[A-Z0-9_]*|API_URL|[A-Z0-9_]*_API_URL`) — `.ts:15`
     says "Keep this var-name set in lockstep with prod-guard.sh";
   - `PLACEHOLDER_VALUE_RE` vs the `.sh` `*changeme*|*'<'*|*'>'*` case;
   - `PLACEHOLDER_HOST_RE` vs the `.sh` RFC-2606 case list — `.sh:101` says "Keep these two case
     patterns in lockstep with prod-guard.ts's PLACEHOLDER_VALUE_RE / PLACEHOLDER_HOST_RE".

   They agree **today** (proven above). But this is the exact drift shape Checks 9b/9bb/9bc were
   built for: a hand-mirrored pair with a comment demanding lockstep and no check behind it. A
   narrowed var-name set on one side would silently unscreen a target on that layer.
   **Suggested fix:** extend Check 8 to pin the other three literals the same way it pins the
   marker regex. Cheap, and closes the gap this audit item existed to find.

   **✅ DONE (session 5).** Check 8 now pins **8 literals across 4 pairs** (was 2 across 1). Two of
   the three added pairs are pinned PER-FILE rather than byte-compared, because the layers
   legitimately spell them in different languages (JS regex vs shell `case` glob) — the same
   approach the marker regex already used. The var-name set IS byte-identical, so both files
   assert the same literal. Tested both directions: all 8 pins PASS on the shipped files, and a
   simulated narrowing of the `.sh` var-name set to `(BASE_URL_[A-Z0-9_]*)` — the exact drift the
   `.sh:32` comment says already happened once historically — is CAUGHT, with the untouched `.ts`
   staying clean.

## 9. Strategic conclusions (context for Block 3, no action needed)

**The moat holds.** Microsoft's shipped agent definitions (pulled from
`microsoft/playwright@main`, not blogs) instruct their healer verbatim: *"mark this test as
`test.fixme()` so that it is skipped"* and *"Do not ask user questions... do the most

this toolkit's reviewer exists to block.

Research backing: LLM oracle correctness **<50%**; oracles cause **~89%** of errors in
LLM-generated tests; LLMs **follow the implementation over the spec** when code is buggy.
A 2026 replication study (11 models, >100k test cases) found coverage/mutation correlations
**invert on buggy code**, and mutation testing becomes *inapplicable* (needs a passing suite).
That is the strongest argument for fault injection: direct bug-detection measurement that
works in the regime where standard proxies don't.

assertion vocabulary — closed vocab is becoming table stakes; the lead is 16-vs-4 plus
negative/`must_fail_when` semantics, a lead in degree not kind. And metamorphic twins for
browser E2E are genuinely novel (research is nearly all REST APIs / autonomous driving) —
expect to explain, not cite.
