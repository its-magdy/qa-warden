plus fresh web research against the 2026 state of the art. **Not** graded on authorship — graded on merit.

## TL;DR

The plugin is **genuinely good engineering with a real, defensible idea — buried under ~30% too much prose.**

- **No correctness bugs** found in `playwright.config.ts`, `package.json`, fixtures, or scripts — pins,

## 1. What is genuinely good — do not touch

1. **The oracle-defense architecture** — the real product:
   - Closed 16-key oracle vocabulary + argument-shape pinning
   - `must_fail_when` reified (reviewer Check 2b) + fault injection at authoring (generator §8b)
   - Value-fidelity (2d) and discriminating-power (2c) checks
   - Web research confirms the native Playwright agents' documented weaknesses are exactly what this layer
     defends: invented-but-plausible assertions, healer patches that change what a test proves, overlapping
     low-value generated tests.
2. **Writable-path separation per agent** (planner→`specs/**`, generator→`tests/`+`page-objects/`,
   healer→+`bugs/`, reviewer→read-only), enforced in frontmatter. This makes "healer must never touch
   assertions" structural, not aspirational.
3. **The script-extraction pattern where it exists** — `prod-guard.sh/.ts`, `check-last-run.sh`,
   `resolve-spec-path.sh`, `bug-status.sh --class`, `retire-delete.sh`. Each one killed a drift class.
   The complaint below is that this stopped at 6 scripts instead of 10.
4. **Best-written files**: `commands/retire.md` (fail-closed `$RG` guard — a missing tool must never read as
   "no consumers ⇒ delete") and `commands/review.md` (CI wiring; "a PR touching tests/ cannot merge without
   the reviewer having run").
5. **Fail-closed-on-inconclusive throughout** — reviewer FAILs an empty diff; run commands treat zero-tests
   as a resolution error; flake-check reports `null` over a fabricated 100%; coverage refuses a single
   percentage. Consistent across all 27 files; this is what makes the toolkit trustworthy.
6. **Honest-limits paragraphs** (coverage on line-coverage, approve on provenance-not-tamper-evidence,
   reviewer on why Check 14 is WARN). Keep every one while cutting around them.
7. **Three-tier context model** with volatility-based staleness + `draft: true` so a fresh date can't
   launder an unverified file.
8. **Technically current substrate**: Playwright 1.62.1 pin, `clientCertificates`, `boxes:true`
   ariaSnapshot, dotenv quiet-mode workaround, run-of-record JSON gating — all verified sound.

## 2. Top problems, ranked

### P1 — `commands/coverage.md` is a shell script wearing a prompt file's clothes (402 lines, ~70% bash)
One 265-line fenced bash block (`coverage.md:50–315`); longer than `agents/reviewer.md`. The plugin already
solved this pattern — `doctor.md` just runs `scripts/doctor.sh`. **Fix: extract `scripts/coverage.sh`
(−312 lines).** Same disease in `impact.md:40–144` (−93 lines via `scripts/impact.sh`).

### P2 — Bug-archaeology tags are load-bearing nowhere (~145 occurrences, ~−250 lines)
`F-16`, `RUN-27`, `A-04`, `P-14`, `HEAL02`, `m-12`… (26 in reviewer.md, 24 in generator.md, 20 in
coverage.md). Session-review IDs meaningless to the runtime model; they license a style where every rule
drags its incident report (e.g. `coverage.md:247–256` spends 10 lines narrating a fixed miscount).
**Fix: keep the corrected rule; move the history to DESIGN.md / memory.**

### P3 — `help.md` hand-duplicates every command description (guaranteed drift)
`help.md:119–141` restates all 21 commands; facts already live in each command's YAML `description:`.
**Fix: render the table from `${CLAUDE_PLUGIN_ROOT}/commands/*.md` frontmatter at runtime.** Keep the
State-read walk (`:41–63`) and "Start here when red" (`:98–104`) — not duplicated anywhere.

### P4 — Prod-guard preamble copy-pasted 7×; "guard first" meta-paragraph 6×
Verbatim-ish in `audit`, `explore`, `gen`, `headless`, `new-spec`, `intake`, `run-smoke`, plus variants in
`heal`, `batch-fix`, and 4 agents. Six files carry a second paragraph whose only content is "the block below
is a safety preamble." **Fix: one canonical 2-line sentence everywhere (−60 lines).** Note the irony:
doctor Check 20 exists solely because this duplication class drifts — inside the scaffold. Nothing polices
it inside the plugin.

### P5 — `run-smoke.md` has ~80 lines of inline shell to run one command
Freshness gate, exit-code guard, sentinel scan, stray-spec scan, open-bug scan (`run-smoke.md:39–117`) are
also implemented in `report.md:66–105`, `headless.md:86–95`, and doctor.sh. The stray-spec loop is
**byte-identical** between `run-smoke.md:91–100` and `report.md:73–80`. **Fix: `scripts/post-run-checks.sh`
(−120 lines across three files).** `report.md` and `run-smoke.md` are 60% the same pipeline — keep both
commands (different intents), single-source the shared 80 lines.

### P6 — Argument parsing re-derived in 7 commands
`setopt shwordsplit` + `set -- $ARGUMENTS` + a zsh explanation appears in `batch-fix`, `explore`,
`coverage`, `headless`, `flake-check`, `impact`, `new-spec`. **Fix: fold into `resolve-spec-path.sh`
(−50 lines).**

### P7 — Reviewer judgment checks have grown into essays
`reviewer.md` Check 2 is a single ~1,100-word paragraph with three nested carve-outs; Check 13's cross-FILE
and cross-FEATURE bullets are ~250 words each. Long prose under-specified as procedure produces the
non-determinism already patched once with Check 2b's "build the matrix, don't eyeball it."
**Fix: give every judgment check the 2b treatment — short rule + enumeration procedure + table to fill.
Restructure, not just trim (~−85 lines falls out).** Also: `generator.md` §8b duplicates doctor.md's
`--verify-invariants` (doctor declares ownership at `doctor.md:192`) and the POM section duplicates
CLAUDE.md (−83 lines).

### P8 — doctor.sh: 720 lines, ~60% comment-essay, redundant checks
- Real code is ~250–300 lines; the rest is incident-history prose with issue-tracker tags.
- **Checks 16/17/18** are the same "spec authored but not compiled" idea sliced three ways → one check with
  a severity flag.
- **Checks 6/9/9b/9c/20** are all "copy A vs copy B drift" → one parameterized mirror-consistency framework
  with a (source, mirror, pattern) table.
- **Checks 13/15b/18/19** are speculative governance WARNs for an idealized workflow that will mostly emit
  noise once a project diverges → move behind an opt-in `--strict` flag.
- Check 9's three-layer `$TMPL` fallback: keep the resolution order, collapse to one failure message.
- `STOCK_VARS` fallback (`doctor.sh:378`) is a second hardcoded copy of what `resync-set.txt` is supposed
  to single-source — a drift trap identical in shape to the ones doctor polices.
- **Target: 720 → ~450–500 lines.**

### P9 — Doc-trio redundancy (README / DESIGN.md / DOCUMENTATION.md / templates/CLAUDE.md)
The same 5–6 core stories (closed vocab, prod-guard two-layer, brain/body split, context tiering, oracle
defenses) told 3–4 times, some **verbatim** (the prod-guard word-boundary explanation). **Fix: README =
entry point only; DESIGN = why; DOCUMENTATION = what/reference; each idea explained once, others link.
~350–400 line reduction.** `playwright.config.ts` comments (~60% of 297 lines) also re-explain CLAUDE.md
decisions → trim ~30%. `package.json`'s six `*_comment` fields (~3,500 chars, incl. a full TS migration
essay) → move to a `VERSION-POLICY.md`.

### P10 — Interactivity/usage boilerplate
The AskUserQuestion main-session-only fact is stated 3× (`approve`, `import-cases`, `intake`); four
commands carry 10-line verbatim usage blocks duplicating their `argument-hint:` frontmatter. A capable
model prints usage on empty args without a script.

## 7. Strategic position vs. native Playwright Agents

Playwright v1.56+ ships planner/generator/healer natively (`npx playwright init-agents`; VS Code /
Claude Code / opencode). The authoring/replay/heal *mechanics* are now commodity, maintained by Microsoft
on Playwright's release cadence. Documented native-agent weaknesses (per playwright.dev + BrowserStack +
independent testing writeups):

- Planner sees only reachable states; can omit risk or produce dozens of overlapping tests.
- Generator can invent plausible-but-wrong assertions.
- Healer patches can silently change what a test proves; a passing rerun ≠ root cause.
- No green-but-wrong gate, no human approval lane, no oracle vocabulary.

**Implication:** stop investing lines in authoring mechanics; invest in the reviewer/governance layer —
the part nobody else ships. Long-term, rebase the trio onto the official substrate (DESIGN.md already says
this). Lead with the framing: *not a competitor to Playwright Agents — the correctness-and-governance
layer on top.*

## 8. Mobile applications — recommendation

**Separate sibling plugin (`qa-mobile`), shared doctrine. Not inside this plugin.**

- Playwright only does mobile-**web** emulation (viewport/touch), not native iOS/Android. The entire
  template layer here (config, fixtures, prod-guard.ts, doctor) is Playwright-shaped and won't transfer.
- 2026 substrate pick: **Maestro** — YAML flows, official **MCP server** (plugs straight into Claude Code,
  so the exploration/planner pattern maps directly), built-in self-healing. **Appium** remains the standard
  for deep/hybrid/system-level coverage but is much heavier to author and heal; consider it a later
  escape hatch, not the default.
- What transfers (the actual asset): closed oracle vocabulary, intake→ideate→approve lane, green-but-wrong
  reviewer checks, fail-closed discipline, prod-guard concept, writable-path separation. The brain is
  reusable; only the body is new.
- **Sequencing: slim this plugin first.** Cloning 8,400 bloated lines doubles the maintenance debt;
  cloning ~6,000 disciplined ones is fine.
